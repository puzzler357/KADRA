## 0. Роль и общие правила (читать первыми, соблюдать всегда)

Ты — senior full-stack инженер и продуктовый дизайнер. Твоя задача — построить десктопное (Windows/macOS/Linux) локальное однопользовательское приложение для кадрового учёта, управления штатным расписанием и генерации справок. Приложение рассчитано строго на одного работника: один пользователь, одно устройство, все данные хранятся локально, синхронизация по сети не предусмотрена. Приложение должно выглядеть современно и презентабельно — категорически не как «1С».

**Незыблемый стек:**
- Клиент: React 18 + TypeScript + Vite + Tailwind CSS.
- UI-компоненты: shadcn/ui (Radix UI).
- Десктоп-оболочка: Tauri 2.0.
- Состояние: Zustand (клиентское) + TanStack Query (серверное).
- Формы: React Hook Form + Zod.
- Локальная БД: SQLite (Tauri SQL plugin) — единственное хранилище данных на устройстве.
- i18n: i18next + react-i18next (языки: `tk`, `en`, `ru`).
- Таблицы: TanStack Table; графики: Recharts.
- Экспорт: ExcelJS (.xlsx), нативный JSON, docxtemplater (.docx); импорт Excel: SheetJS.
- Бэкенд: локальный, встроенный в приложение (например, Node/Express в составе десктоп-оболочки), работающий только с локальной SQLite. Внешний сетевой сервер, общая БД и удалённый доступ не используются — приложение полностью автономно на одном устройстве. Локальная авторизация: единственная учётная запись владельца устройства.

**Правила разработки:**
1. Строгий TypeScript (`strict: true`), никакого `any` без явного обоснования.
2. Единые Zod-схемы для валидации на клиенте и сервере.
3. Все пользовательские строки — только через i18n, никаких хардкод-текстов.
4. Каждый экран имеет состояния: загрузка (skeleton), пусто (empty state), ошибка, успех.
5. Доступность (a11y): семантика, фокус, контраст, работа с клавиатуры.
6. Атомарные коммиты, понятные имена, комментарии только там, где логика неочевидна.
7. После каждого этапа — краткий отчёт: что сделано, как проверить, что дальше.

## 1. Дизайн-система (задать до написания экранов)

Цель — чистый, «дышащий», презентабельный интерфейс уровня современных SaaS-продуктов.

**Шаг 1.1. Палитра.** Настрой токены в Tailwind:
- Нейтральная база: `slate` (фон, текст, границы).

**Шаг 1.4. Микровзаимодействия.** Плавные переходы (150–200 мс), hover/active-состояния, тосты для действий, скелетоны при загрузке, аккуратные анимации появления (без излишеств).

**Шаг 1.5. Каркас интерфейса:**

**Готово, когда:** есть работающий шаблон страницы с сайдбаром, топбаром, переключением тем и языка, и он выглядит презентабельно на десктопе при разных размерах окна.

## Финальный критерий приёмки всего проекта

Приложение собирается как десктоп-приложение (Windows/macOS/Linux) и работает 100% локально на одном устройстве под единственным пользователем, без сети, внешнего сервера и синхронизации; все данные хранятся в локальной SQLite; интерфейс работает на туркменском, английском и русском с выбором языка по умолчанию; работают штатное расписание с версиями, конструктор справок, выгрузка отчётов в Excel и JSON, файловый импорт/экспорт (Excel/XML/CSV) и генерация Word, централизованный модуль настроек с многоуровневым сбросом данных; дизайн современный, презентабельный и не похож на «1С».
