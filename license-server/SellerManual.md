# Руководство продавца KADRA

Как продавать, активировать, продлевать и отзывать лицензии. Написано для
того, кто продаёт KADRA, а не программирует его: все действия выполняются
мышью в панели License Manager, командная строка нужна только при первой
настройке.

Технические подробности для системного администратора — в [README.md](README.md),
правила и обоснования — в [LICENSING.md](../LICENSING.md).

---

## 1. Из чего всё состоит

| Программа | Где работает | Зачем |
| --- | --- | --- |
| **KADRA** | у клиента | само приложение; проверяет лицензию при каждом запуске |
| **Сервер лицензий** | ваш сервер (или ваш компьютер) | хранит клиентов, лицензии и компьютеры, выпускает файлы лицензий |
| **License Manager** | веб-страница этого сервера | ваш рабочий экран: вся работа с лицензиями здесь |

Сервер лицензий и `server.ts` в корне проекта — разные программы: второй
нужен только для запуска KADRA в браузере при разработке и к лицензиям
отношения не имеет.

**Клиент может работать без вашего сервера.** Файл лицензии лежит у него на
компьютере и действует сам по себе. Сервер нужен в момент продажи, продления
и смены компьютера.

---

## 2. Подготовка (делается один раз)

### 2.1. Ключ подписи

Каждый файл лицензии подписывается вашим секретным ключом. KADRA верит только
файлам с этой подписью: подделать лицензию без ключа нельзя.

```
node tools/kdr-license keygen --kid kdr-2026-1
```

Команда спросит пароль ключа (не короче 12 символов) и создаст два файла:

- `~/.kdr-license/keys/kdr-2026-1.key` — **секретный ключ**;
- запись в `src-tauri/license-keys.json` — открытая часть, она вшивается в KADRA
  при сборке.

> **Сделайте две резервные копии секретного ключа на разных носителях
> (флешки, внешний диск) и храните отдельно от компьютера.** Потеря ключа
> означает, что вы не сможете выпускать и продлевать лицензии для уже
> проданных копий KADRA. Восстановить его невозможно.

Пароль ключа запомните или храните в менеджере паролей. Без него ключ не
откроется.

### 2.2. Администратор панели

```
cd license-server
npm run admin -- add owner
```

Команда спросит пароль (ввод не отображается) и напечатает **секрет для
приложения-аутентификатора** — длинную строку заглавными буквами. Введите её
в Google Authenticator, Aegis или подобное приложение на телефоне: «Добавить
вручную» → ввести секрет → тип «по времени».

Секрет показывается один раз. Если он потерян, создайте администратора заново
той же командой — пароль и секрет заменятся на новые.

### 2.3. Запуск сервера

На рабочем сервере:

```
cd license-server
npm start
```

Перед сервером должен стоять nginx или Caddy с HTTPS — без него вход в панель
не работает, это защита от перехвата пароля. Переменные окружения перечислены
в [README.md](README.md).

Для проверки на своём компьютере есть упрощённый запуск:

```
cd license-server
npm run dev
```

Он использует тестовую базу и **ключ разработчика**: такие лицензии принимает
только отладочная сборка KADRA и не принимает настоящая. Для продажи он не
годится.

## 3. Основные понятия

Их пять, и они связаны цепочкой:

```
Клиент (организация)
  └─ Лицензия ────────── ключ лицензии KDR-XXXXX-XXXXX-XXXXX-XXXXX
       │                 тариф, режим, число мест, оплачено до
       ├─ Активация № 1 ─ компьютер кадровика Анны
       ├─ Активация № 2 ─ компьютер начальника отдела кадров
       └─ Активация № 3 ─ компьютер директора
```

| Понятие | Что это | Пример номера |
| --- | --- | --- |
| **Клиент** | организация, которая платит | `CUST-000001` |
| **Лицензия** | договор с этой организацией: тариф, срок, сколько компьютеров | `KDR-2026-000001` |
| **Ключ лицензии** | строка, которую вы передаёте клиенту для активации | `KDR-67332-M0DER-BMNWK-8QVC9` |
| **Активация** | один конкретный компьютер, занявший место | `ACT-58b0d52d` |
| **Место** | сколько компьютеров разрешено по лицензии | `3` |

**Одно место = один компьютер + один пользователь Windows.** Если за одним
компьютером работают два кадровика под разными учётными записями Windows,
это два места: у каждого своя база и своя активация.

## 4. Как лицензия закрепляется за клиентом и за компьютером

Это главный вопрос, поэтому разберём по шагам.

### 4.1. За клиентом — ключом лицензии

При создании лицензии сервер выдаёт **ключ** вида
`KDR-67332-M0DER-BMNWK-8QVC9`. Вы передаёте его клиенту — это его
«пароль» для активации.

На сервере ключ **не хранится**: сохраняется только его хэш, как у пароля.
Поэтому:

- ключ показывается **один раз**, в момент создания лицензии;
- если клиент его потерял, посмотреть ключ нельзя — создаётся новая лицензия;
- кража базы сервера не даёт злоумышленнику ключей.

Ключ не привязан к компьютеру. Им можно активировать столько компьютеров,
сколько мест в лицензии.

### 4.2. За компьютером — при активации

Когда клиент вводит ключ в KADRA, приложение отправляет на сервер два «слепка»
компьютера:

1. **Отпечаток компьютера** — три числа, каждое получено из характеристик
   машины: идентификатор установки Windows, идентификатор материнской платы и
   серийный номер системного диска. Сами характеристики не передаются, только
   необратимые хэши.
2. **Ключ устройства** — пара ключей, которую KADRA создаёт прямо на этом
   компьютере. Секретная половина остаётся на нём, защищённая средствами
   Windows (DPAPI) и привязанная к учётной записи пользователя. Открытая
   половина уходит на сервер.

Сервер выпускает **файл лицензии именно для этой пары**: он содержит отпечаток
и открытый ключ устройства, и всё это скреплено вашей подписью.

Дальше KADRA при каждом запуске проверяет:

| Проверка | Что произойдёт при несовпадении |
| --- | --- |
| Файл подписан вашим ключом | «Файл лицензии повреждён» |
| Отпечаток совпадает хотя бы **2 из 3** | «Лицензия выпущена для другого компьютера» |
| Ключ устройства на месте и совпадает | «Нужна повторная привязка» |

**Почему 2 из 3.** Замена диска, материнской платы или переустановка Windows
меняют один компонент из трёх. Лицензия продолжает работать: клиенту не нужно
обращаться к вам из-за замены жёсткого диска.

**Почему нельзя скопировать.** Если скопировать папку с лицензией на другой
компьютер, не совпадёт ни отпечаток, ни ключ устройства: секретная половина
ключа зашифрована средствами Windows и на чужой машине не расшифруется.

### 4.3. Что это даёт на практике

| Ситуация | Результат |
| --- | --- |
| Клиент переставил KADRA на том же компьютере | Работает, ничего делать не нужно |
| Заменил диск или материнскую плату | Работает (2 из 3 совпадают) |
| Переустановил Windows | Онлайн — восстановится само; офлайн — нужен новый файл от вас |
| Скопировал папку KADRA на другой компьютер | Только чтение, «лицензия для другого компьютера» |
| Отдал ключ знакомому | Знакомый займёт одно из мест; когда места кончатся, активация не пройдёт |

## 5. Продажа: от клиента до работающего KADRA

### Шаг 1. Создать клиента

Вкладка **«Клиенты»** → кнопка **«Новый клиент»**. Название обязательно,
остальное (контактное лицо, почта, телефон) — для вашего удобства.

### Шаг 2. Создать лицензию

Вкладка **«Лицензии»** → **«Новая лицензия»**. Поля формы:

| Поле | Что выбрать |
| --- | --- |
| **Клиент** | организация из шага 1 |
| **Тариф** | Бессрочная, Годовая, Квартальная или Месячная |
| **Режим** | «Онлайн» или «Офлайн (обмен файлами)» — см. ниже |
| **Мест (компьютеров)** | сколько компьютеров сможет работать одновременно |
| **Начало оплаченного периода** | обычно сегодня; можно задним числом |
| **Версии KADRA до** | `1.99.99` — лицензия покроет все версии 1.x; пусто — все версии |
| **Редакция**, **Модули** | для будущего разделения возможностей; сейчас можно оставить как есть |

**Какой режим выбрать:**

| | Онлайн | Офлайн |
| --- | --- | --- |
| Нужен интернет у клиента | да, хотя бы иногда | нет, никогда |
| Активация | ввёл ключ — готово | обмен файлами через вас |
| Продление | клиент получает сам | вы высылаете файл |
| Отозвать досрочно | можно (в течение 30 дней) | нельзя до конца оплаченного срока |
| Месячный тариф | можно | **нельзя** (запрещено системой) |

По умолчанию выбирайте **онлайн**: меньше ручной работы. Офлайн — для
клиентов без интернета.

### Шаг 3. Передать ключ

После создания панель покажет **ключ лицензии** на тёмном поле с кнопкой
«Копировать». Это единственный раз, когда он виден. Скопируйте и передайте
клиенту любым способом.

### Шаг 4. Клиент активирует KADRA

Клиент открывает KADRA и видит экран «Активация KADRA».

**Если лицензия онлайн:** вводит ключ → **«Активировать через интернет»**.
Через секунду приложение открывается. Всё.

**Если лицензия офлайн:**

1. Клиент вводит ключ и нажимает **«Создать файл запроса»**, сохраняет файл
   `activation_request.kdrreq` и присылает вам (почтой, мессенджером, на флешке).
2. Вы: вкладка **«Офлайн-файлы»** → выбираете полученный файл. Панель покажет
   раздел **«Что просит файл»**: какой компьютер, какая лицензия, сколько мест
   занято. Ничего ещё не изменилось.
3. Нажимаете **«Выпустить файл лицензии»** — скачается файл `.kdrlic`.
4. Отправляете его клиенту. Клиент нажимает **«Импортировать файл»** и
   выбирает его.

## 6. Продление

### Клиент заплатил — что нажать

Вкладка **«Лицензии»** → нужная лицензия → кнопка **«Продлить»**.

| Поле | Что указать |
| --- | --- |
| **Периодов** | 1 — один срок тарифа (год для годового), 2 — два срока и так далее |
| **Способ оплаты** | Наличные, Банковский перевод, Карта, Другое |
| **Дата фактической оплаты** | день, когда деньги получены (важно, см. ниже) |
| **Сумма**, **Валюта** | для учёта, можно пропустить |
| **Номер квитанции** | номер приходного ордера или платёжного поручения |

**Почему важна дата оплаты.** От неё зависит новый срок:

- заплатил **вовремя** (до конца оплаченного периода плюс льготные 7 дней) —
  новый срок считается от старой даты окончания, клиент не теряет дни;
- заплатил **позже** — новый срок считается от дня оплаты, клиент не платит
  за время, когда не пользовался.

Пример: оплачено до 30 сентября.
Заплатил 2 октября (в льготные дни) → новый срок до 30 сентября следующего года.
Заплатил 20 октября → новый срок до 20 октября следующего года.

### Что происходит дальше

- **Онлайн-клиент** получит новый срок сам, при ближайшей проверке. Если нужно
  немедленно — попросите нажать «Проверить лицензию» в Настройках.
- **Офлайн-клиенту** файлы для всех его компьютеров **скачаются сразу** при
  нажатии «Продлить». Отправьте их клиенту, запрос от него не нужен.

### Если клиент не заплатил

| Когда | Что видит клиент |
| --- | --- |
| Срок истёк, идут льготные дни (7) | Работает полностью, над страницей жёлтый баннер «Подписка закончилась N дней назад» |
| Льготные дни кончились | Только просмотр: данные видны, отчёты и выгрузка в Excel работают, но изменить ничего нельзя |

**Данные клиента никогда не блокируются и не шифруются.** Даже с истёкшей
лицензией он видит свои кадровые данные, печатает отчёты и делает резервную копию.
Запрещено только вносить изменения.

## 7. Частые ситуации у клиентов

### Клиент переустановил Windows

Отпечаток совпадает на 2 из 3, но ключ устройства пропал. KADRA пишет «Нужна
повторная привязка».

- **Онлайн:** клиент нажимает «Проверить лицензию» — привязка восстановится
  сама. Переносом это не считается, лимит не тратится.
- **Офлайн:** клиент создаёт файл запроса (кнопка «Создать файл запроса»),
  присылает вам, вы обрабатываете его на вкладке «Офлайн-файлы» так же, как
  при активации.

### Клиент меняет компьютер, старый работает

1. На **старом** компьютере: Настройки → Лицензия → **«Деактивировать
   компьютер»**. Онлайн — место освободится сразу; офлайн — KADRA сохранит файл
   `.kdrdeact`, клиент пришлёт его вам, а вы загрузите на вкладке
   «Офлайн-файлы».
2. На **новом** компьютере: обычная активация тем же ключом.

### Клиент меняет компьютер, старый сломан

Деактивировать нечего, место занято «мёртвым» компьютером.

1. Клиент активирует новый компьютер обычным способом. Он получит отказ «все
   места заняты» (онлайн) или вы увидите это при обработке файла запроса.
2. Вы открываете вкладку **«Офлайн-файлы»** и загружаете его файл запроса,
   либо находите лицензию и освобождаете место вручную: карточка лицензии →
   строка старого компьютера → **«Освободить»**.
3. При обработке запроса отметьте галочку **«Одобряю перенос»**.

Перенос всегда требует вашего одобрения — сам по себе он не произойдёт. Сверх
двух переносов за год панель запросит дополнительную галочку «Разрешить сверх
лимита» и запишет это в журнал как предупреждение.

### У клиента «часы переведены назад»

KADRA заметил, что дата на компьютере раньше, чем время, которое он уже видел.
Причины бывают безобидные: села батарейка в компьютере, неверный часовой пояс.

1. Сначала попросите клиента **поставить правильную дату и время** — обычно
   этого достаточно, состояние снимется само.
2. Если не помогло (часы однажды убежали далеко вперёд):
   - **онлайн:** клиент нажимает «Проверить лицензию», время возьмётся с сервера;
   - **офлайн:** карточка лицензии → нужный компьютер → кнопка **«.kdrclock»** →
     скачается файл разблокировки, отправьте его клиенту, он импортирует его
     кнопкой «Импортировать файл».

### Клиент не платит, нужно отключить

Карточка лицензии → **«Отозвать»**, с указанием причины.

| Режим лицензии | Когда подействует |
| --- | --- |
| Онлайн | при ближайшей проверке у клиента, не позже 30 дней |
| Офлайн | **никогда**; файл доработает до конца оплаченного срока |

Это свойство офлайн-лицензий, а не недоработка: файл у клиента на диске, и
дотянуться до него нечем. Поэтому офлайн продавайте длинными сроками.

## 8. Платежи

Вкладка **«Платежи»** показывает все оплаты: и те, что вы внесли кнопкой
«Продлить», и те, что пришли автоматически.

### Автоматическое продление

Если ваш банк, платёжный шлюз или 1С умеют отправлять уведомления об оплате,
их можно подключить: оплата будет сама продлевать лицензию.

1. Вкладка «Платежи» → **«Новый источник»** → имя латиницей, например `bank`.
2. Панель покажет **адрес** и **секрет** — передайте их тому, кто настраивает
   отправку уведомлений. Секрет показывается один раз.
3. Формат уведомления описан в [README.md](README.md), раздел «Webhook оплаты»,
   с примерами.

Источник можно отключить кнопкой «Отключить»: уведомления от него перестанут
приниматься, секрет при этом сохранится.

Для офлайн-лицензии автоматическая оплата продлит срок, но файлы нужно
выпустить и отправить вам — в списке оплат появится ссылка «выпустить файлы».

## 9. Подозрительные события

Вкладка **«События»**, раздел **«Подозрительное»**:

| Показатель | Что значит |
| --- | --- |
| **Ошибки подписи** | кто-то присылал подделанные запросы |
| **Возможные клоны** | счётчик обращений компьютера пошёл назад: похоже, копию системы запускают параллельно |
| **Исчерпанный лимит переносов** | лицензия слишком часто переезжает между компьютерами |

Компьютер, помеченный как возможный клон, **продолжает работать**: причины
бывают честные — восстановление из резервной копии, откат виртуальной машины.
Разберитесь с клиентом; если всё в порядке, нажмите **«Снять подозрение»** в
карточке лицензии.

Ниже — журнал всех действий: кто и когда создал лицензию, выпустил файл, вошёл
в панель. Галочка «Только предупреждения» оставит лишь тревожные записи.

## 10. Проверка всего механизма своими руками

Пройдите этот сценарий один раз — и вы увидите все состояния, с которыми
столкнутся клиенты. Занимает около 20 минут. Используется отладочная сборка
KADRA и ключ разработчика, настоящие лицензии не затрагиваются.

**Что понадобится:** два окна PowerShell и KADRA, запущенный командой
`npm run tauri:dev`.

### Подготовка

Окно 1 — сервер лицензий (не закрывайте его):

```
cd D:\ОК\KADRA\license-server
npm run dev
```

Окно 2 — для команд. Откройте панель http://127.0.0.1:8787/admin/ и войдите.

### Проверка 1. Без лицензии — только чтение

Запустите KADRA. На чистой установке (владелец ещё не создан) вы увидите экран
«Активация KADRA»: приложение не даёт работать, но и не требует интернета —
предлагает оба способа. Если на этом компьютере KADRA уже использовался,
приложение откроется в режиме только чтения: войти и смотреть можно, над
страницей — красный баннер с кнопкой «Активировать».

### Проверка 2. Продажа и активация

1. В панели создайте клиента и годовую **онлайн**-лицензию на 1 место.
2. Скопируйте ключ.
3. В KADRA вставьте ключ → «Активировать через интернет».

Приложение открылось. В панели, в карточке лицензии, появился компьютер со
статусом ACTIVE и строка в «Выданных файлах».

### Проверка 3. Что видно клиенту

В KADRA: Настройки → раздел **«Лицензия»**. Там номер, тариф, до какой даты
оплачено, когда была последняя проверка.

Нажмите **«Проверить лицензию»** — внизу справа появится сообщение «Лицензия
обновлена с сервера», а в панели номер ревизии вырастет на единицу.

### Проверка 4. Отзыв

В панели: карточка лицензии → «Отозвать» → причина → подтвердить.

В KADRA нажмите «Проверить лицензию». Приложение перейдёт в режим только
чтения, над страницей появится красный баннер. Попробуйте добавить
сотрудника — не сохранится, приложение скажет почему. Откройте отчёт и
выгрузку в Excel — работают.

### Проверка 5. Возврат к работе

Создайте новую лицензию (отозванная не восстанавливается) и активируйте KADRA
её ключом. Приложение снова работает полностью.

### Проверка 6. Офлайн-путь

1. Создайте **офлайн**-лицензию, скопируйте ключ.
2. В KADRA: Настройки → Лицензия → «Деактивировать компьютер» → «Создать файл
   подтверждения», сохраните `.kdrdeact`.
3. В панели: «Офлайн-файлы» → загрузите этот файл → «Освободить место».
4. В KADRA на экране активации вставьте новый ключ → «Создать файл запроса».
5. В панели: «Офлайн-файлы» → загрузите `.kdrreq` → посмотрите раздел «Что
   просит файл» → «Выпустить файл лицензии».
6. В KADRA: «Импортировать файл» → выберите скачанный `.kdrlic`.

### Проверка 7. Продление наличными

Карточка лицензии → «Продлить» → способ «Наличные», сумма, номер квитанции.
Для офлайн-лицензии сразу скачается новый файл. Откройте вкладку «Платежи» —
оплата в списке.

### Уборка

Тестовая база лежит в `tools\kdr-license\dev\license.db` и не связана с
рабочей. Удалите файл, чтобы начать с чистого листа.

## 11. Резервные копии и безопасность

| Что | Где | Как часто |
| --- | --- | --- |
| **Секретный ключ подписи** | `~/.kdr-license/keys/` | один раз, две копии на разных носителях |
| **База сервера** | путь из `KDR_LICENSE_DB` | ежедневно |
| Пароль и секрет администратора | у вас | при создании |

**Потеря ключа подписи невосполнима:** проданные копии KADRA продолжат работать
по уже выданным файлам, но ни продлить, ни перенести, ни активировать заново
вы их не сможете. Понадобится новый ключ, новая версия KADRA и перевыпуск всех
лицензий.

**Потеря базы** менее опасна: лицензии у клиентов не перестанут работать, но
вы потеряете список, кто что купил, и не сможете продлевать. Восстанавливается
из резервной копии.

Что **нельзя** узнать задним числом:

- ключ лицензии клиента (храните свой список при продаже или создавайте новую лицензию);
- пароль администратора (только задать новый);
- секрет для кодов входа (только создать администратора заново).
